# AIWeberAgent

Нейросеть-помошник в написании кода

## Практический план действий для старта:

1) Не пытайтесь обучать с нуля. Выберите небольшую, но качественную открытую модель (например, T5-Small или StarCoder2-3B).
2) Соберите датасет. Напишите скрипт на Node.js или Python, который возьмет 5–10 тысяч коммитов из открытых JS-проектов, где в сообщении коммита есть слова refactor, cleanup, simplify. Извлеките diff этих коммитов — это будут готовые пары для обучения рефакторингу.
3) Токенизация: Используйте специализированный токенизатор для кода (например, от StarCoder2 или Tree-sitter), чтобы модель видела не просто текст, а токены ключевых слов, переменных и отступов.
4) Запустите дообучение. Используйте Hugging Face Transformers с accelerate и LoRA-адаптером. Это можно сделать на одной видеокарте с 24 ГБ видеопамяти (например, RTX 4090) или в облаке.
5) Упакуйте в API. Оберните модель в простой FastAPI-сервис.
6) Напишите VS Code Extension. Как фронтендеру, вам будет проще всего написать расширение для VS Code, которое будет отправлять выделенный код на ваш локальный или облачный эндпоинт и показывать результат в сайдбаре.


## Необходимые действия:

- Вы пишете скрипт на Node.js, который собирает 10 000 примеров рефакторинга из GitHub и сохраняет их в файл data.jsonl.
- Вы запускаете скрипт на Python (train.py), который читает data.jsonl и за несколько часов дообучает StarCoder2-3B.
- Вы запускаете сервер на Python (api.py с FastAPI), который держит модель в памяти. Он слушает, например, localhost:8000.
- Вы открываете VS Code. Ваше расширение на Node.js (TypeScript) видит выделенный код, делает fetch('http://localhost:8000/completion', ...) и показывает результат во всплывающем окне.


##  Архитектура решения для сбора датасета (dataset-creater):
1) Поиск репозиториев: Используем search/repositories с запросом language:JavaScript refactor, чтобы найти проекты, где рефакторинг — часть процесса.
2) Сбор коммитов: Для каждого найденного репозитория запрашиваем commits с query-параметром q=refactor. Это отфильтрует историю коммитов.
3) Извлечение диффа: Для каждого коммита запрашиваем его подробности, чтобы получить URL на сырой diff (поле commit.message и files с patch).
4) Очистка и парсинг: Разделяем diff на старый (before) и новый (after) код. Удаляем служебные строки (---, +++, index...).
5) Устойчивость: Скрипт использует очередь с задержкой (rate limiting), сохраняет прогресс в файл каждые 100 примеров и корректно обрабатывает ошибки сети и отсутствие диффов.
